## 2026-07-23 第 4 轮：执行落地 + 架构纠正

**执行启动**：按第 3 轮方案开始执行——git init、克隆 Quartz、内容迁移、配置、构建。

**过程中发现的关键事实**：

1. **克隆得到的是 Quartz v5.0.0**（非 v4）。配置为 YAML（`quartz.config.yaml`），插件为 `@quartz-community/*` npm 包；`markdownLinkResolution` 默认是 `shortest`（须显式设 `absolute`）；构建前需 `npm run install-plugins` 生成 `.quartz/plugins` 索引。
2. **架构认知被用户纠正**：用户指出「为什么会修改旧文件？流程应是自动从 vault 复制到 quartz/content，不应影响 vault；镜像到 wiki 后将 vault 删除，下次提供新 vault 再对比增改」。
   - 纠正：vault 是**临时输入**（gitignore），`quartz/content/` 是**被追踪的规范内容源**；转换发生在镜像这一步，不碰 vault；构建期无 rsync。
   - 已把转换后的内容镜像到 `quartz/content/`（15 文件），vault 现处于被改动状态（待清理，已 gitignore）。
3. **构建踩坑**：首次构建报 `Could not resolve "../../.quartz/plugins"`（未生成插件索引）与 `Found 0 input files`（根 .gitignore 的 `quartz/content/` 被 globby 的 `gitignore:true` 排除）。修复见 03。
4. **baseUrl 格式**：v5 要求不含协议/首尾斜杠、含子路径；先用占位 `your-username.github.io/chinese-architecture-wiki`。

**本地构建验证通过**：Parsed 15 Markdown files / Emitted 108 files；内部链接 `absolute` 模式解析正确（`../concepts/jian` 等）；sitemap URL 格式正确。仅剩 KaTeX 对公式中中文变量名的警告（非错误）。

## 2026-07-23 第 3 轮：Claude Code 评审反馈 + Slug 化决策

**背景**：将第 2 轮确认的方案交由 Claude Code 评审。反馈认为整体方向（选型、架构、同步策略）正确，但指出 4 个执行层问题：

1. **rsync 缺少 `--exclude`**：当前命令会把 `.obsidian/`、`templates/`、`all.base` 拷进 `content/`，被 Quartz 当作页面渲染。需排除。
2. **《》书名号文件名风险被低估**：`refs/清工部《工程做法则例》.md` 等路径，URL-encode 后变成 `%E3%80%8A...%E3%80%8B`，可读性极差，且部分静态服务存在边缘情况。需二选一：保留中文书名号文件名（接受丑 URL），或改用 slug 并在 frontmatter 保留显示名。
3. **Quartz v4 初始化方式需明确**：标准做法是 `git clone https://github.com/jackyzha0/quartz.git quartz` 后删除 `.git`，不是 `npm init`。原方案描述模糊。
4. **仓库尚未 git 初始化**：当前目录不是 git repo，但方案依赖 git 做版本追踪与回滚。这是执行第一步，原方案未显式列出。

**用户决策**：

- **全面将中文文件名改为 slug 格式**（采用反馈方案二）。由于当前 `aliases` 字段恰好存储了名称，改 slug 不会丢失显示信息。
- **frontmatter 重构**：从 Obsidian 迁到 wiki 时，把 `aliases` 改为更合适的字段。需考虑「有些 concept 自带别名」（主副名称/多名称）的适应性。

**方案组的设计（已落实进 `01-实现方案.md`）**：

1. **frontmatter 字段规范**（适配 Quartz v4 原生语义）：
   - `title`（字符串）：主名称/规范名——用于图谱节点、搜索、浏览器标签页、页面标题。
   - `aliases`（数组）：同义名/俗称/简称——用于搜索命中与别名解析。
   - 规则：原 `aliases` 中与文件名同义的首项 → 移入 `title`；其余真正同义名 → 保留在 `aliases`。
   - 适应性四类情形均有举例：单名（大式建筑）、主+俗称（面阔/面宽）、全称+简称（清工部《工程做法则例》/《则例》）、编号章节（1-明清建筑类型 → title: 明清建筑形式类型）。

2. **Slug 方案**：拼音、连字符分词、去除《》与冗余前缀（保留可识别性）。完整映射表见 01 §4.2.4。书名号《》仅保留在 `title` 显示名中，不进入文件名/URL。

3. **链接解析验证（关键发现）**：核查 Quartz v4 `CrawlLinks` 的 `markdownLinkResolution` 选项——默认值 `"absolute"` 的含义是「从 content 根目录解析路径」（已对照官方文档 `docs/plugins/CrawlLinks.md` 与 DeepWiki 确认）。现有 vault 的链接写法（如 `concepts/面阔.md`，无 `../`）正是 root-relative，**与 Quartz 默认 absolute 模式天然匹配**，从任意目录层级均可正确解析。故：
   - slug 化后只需把链接中的中文文件名替换为 slug 文件名，路径结构与链接文本不变；
   - 无需改写为 `[[wikilink]]`，无需补 `../`，正文改动最小化；
   - 配置中显式写 `markdownLinkResolution: "absolute"` 以防默认值变更。

4. **rsync `--exclude`**：补充排除 `.obsidian/`、`templates/`、`*.base`、`.DS_Store`。

5. **Quartz 初始化**：明确为 `git clone` + `rm -rf .git`，纳入本仓库管理（非 `npm init`）。

6. **执行步骤前置 git init**：新增为执行第 0 步，并给出根 `.gitignore` 内容。

**结论**：4 项反馈全部落实，slug 化与 frontmatter 规范作为新增决策写入 01 §4.2 与 §7。下一步进入执行（git init → Quartz clone → slug 重命名与链接更新 → 配置 → 部署流水线 → 本地预览 → 推 GitHub）。
