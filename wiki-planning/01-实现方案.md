## 1. 背景与目标

以现有 Obsidian vault 为参考，搭建一个**开源、可部署在 GitHub 上**的公开 wiki 站点。

核心诉求：现代美观排版；便于后续插图片；支持关系网可视化；开源托管；尽量复用现有内容与链接约定。

## 2. 现有 Vault 架构分析

```
chinese-architecture-wiki-vault/      # Obsidian vault（临时输入）
├── index.md              # 首页
├── concepts/             # 术语概念条目
├── refs/                 # 参考文献（含分章节子目录）
├── topics/               # 主题归类（预留）
├── templates/            # 新建条目模板
├── all.base              # Obsidian Bases 配置（编辑器产物）
└── .obsidian/            # Obsidian 配置（编辑器产物）
```

内容约定：

| 特性 | 现有写法 | 说明 |
|------|----------|------|
| 链接 | `[面阔](concepts/面阔.md)` | **root-relative**（无 `../`），从 vault 根算起 |
| 脚注引用 | `[^1]: [面宽和进深](refs/....md)` | 脚注带链接 |
| 数学公式 | `$开间面阔 = 斗栱攒数 * 斗口 * 11$` | 行内 LaTeX（含中文变量名，见 §6 已知问题） |
| Frontmatter | `aliases / created / modified / tags` | YAML |
| 分类 | `tags: [术语解释, 做法规定, …]` | 标签体系 |

**关键结论**：内容已是「干净 Markdown + root-relative 链接 + LaTeX + 脚注」。root-relative 链接与 Quartz `markdownLinkResolution: "absolute"`（从 content 根解析）天然匹配——已实测验证（见 §5）。

## 3. 方案选型：Quartz v5

克隆 `jackyzha0/quartz`（v5.0.0）获得。v5 相对早期版本的关键变化（执行中确认）：

- **配置为 YAML**（`quartz.config.yaml`），非 `quartz.config.ts`；加载器读取 `quartz.config.yaml`（用户覆盖），否则 `quartz.config.default.yaml`，**不合并**（用户配置须完整）。
- **插件为 `@quartz-community/*` npm 包**，在 `plugins:` 段配置；构建前需 `npm run install-plugins` 生成 `.quartz/plugins` 索引（否则报 `Could not resolve "../../.quartz/plugins"`）。
- `markdownLinkResolution` **默认 `shortest`**（非 v4 的 `absolute`），须显式设为 `absolute` 以匹配 vault 的 root-relative 链接。
- **页面内链接尽量用相对 URL**（`./`、`../`），天然适配 GitHub Pages 子路径；`baseUrl` 仅用于 sitemap/RSS/canonical 等绝对 URL。

选型理由：原生 graph view + backlinks + 相对链接 + KaTeX + Mermaid + 官方 GitHub Action；root-relative 链接零改动。

## 4. 详细设计

### 4.1 仓库结构与内容流（纠正后架构）

```
chinese-architecture-wiki/              # GitHub 仓库根（git 仓库）
├── chinese-architecture-wiki-vault/    # 【临时输入】Obsidian vault（gitignore）
│                                       #   用户提供 → 镜像+转换到 content → 删除
├── quartz/                             # 发布层（Quartz v5）
│   ├── content/                        # 【追踪的规范内容源】转换后的 slug 内容
│   ├── quartz.config.yaml              # 站点配置（追踪）
│   ├── quartz.config.default.yaml      # 上游默认配置（追踪，作参考）
│   ├── package.json / package-lock.json
│   └── …（Quartz 源码，追踪；node_modules/public/.quartz 忽略）
├── .github/workflows/deploy.yml        # 部署流水线（追踪）
├── wiki-planning/                      # 规划与运维文档（追踪）
├── .gitignore
└── README.md
```

**核心架构（纠正第 3 轮的错误认知）**：

- **vault 是临时输入**，不是被追踪的内容源，也不在仓库中长期存在。每次更新由用户提供一个 vault 快照（Obsidian 导出，保持原样、中文文件名）。
- **`quartz/content/` 是被版本追踪的规范内容源**。它由 vault 经「镜像 + 转换」得到（slug 文件名、`title`/`aliases` frontmatter、slug 链接）。
- **构建直接读 `content/`**，不再有构建期 rsync。CI 只做 `npm ci → npm run install-plugins → npx quartz build`。
- **vault 不被改动**：镜像是对 vault 的只读拷贝 + 转换，写入 `content/`；镜像完成后 vault 即可删除。

> 与第 2–3 轮方案的差异：原方案把 vault 当作被追踪的内容源、在 vault 里就地改造、构建期 rsync 同步到 gitignore 的 `content/`。**纠正后正好相反**：vault 是临时输入（gitignore），`content/` 是追踪源；转换发生在镜像这一步，不碰 vault 原件；构建期无 rsync。

### 4.2 文件名 Slug 化与 frontmatter 规范

> 解决中文/书名号文件名 URL 不安全的问题。转换在「vault → content 镜像」时应用。

**frontmatter 字段**（适配 Quartz v5 原生语义）：

| 字段 | 类型 | 作用 |
|------|------|------|
| `title` | 字符串 | 主名称/规范名（图谱节点、搜索、标签页、页面标题） |
| `aliases` | 数组 | 同义名/俗称/简称（搜索命中、别名解析） |
| `created`/`modified` | 日期 | 时间线 |
| `tags` | 数组 | 分类（图谱分色） |

**规则**：原 `aliases` 中与文件名同义的首项 → 移入 `title`；其余真正同义名 → 保留在 `aliases`。适应性四类情形：

| 情形 | 原 → 新 |
|------|---------|
| 单名 | `aliases:[大式建筑]` → `title:大式建筑` |
| 主+俗称 | `aliases:[面阔,面宽]` → `title:面阔`，`aliases:[面宽]` |
| 全称+简称 | `aliases:[清工部《工程做法则例》,《工程做法》,《则例》]` → `title:清工部《工程做法则例》`，`aliases:[《工程做法》,《则例》]` |
| 编号章节 | `aliases:明清建筑形式类型` → `title:明清建筑形式类型` |

**Slug 规则**：拼音无声调、连字符分词、省略助词（「的」）、保留功能连词（「与」「和」）、去除《》、省略冗余前缀、保留章节编号前缀。

### 4.4 构建与部署

**本地构建序列**（已验证）：

```bash
cd quartz
npm install                 # 装 @quartz-community/* 等依赖
npm run install-plugins     # 生成 .quartz/plugins 索引（必须，否则构建报错）
npx quartz build            # 输出到 public/
```

**部署流水线** `.github/workflows/deploy.yml`（仓库根，非 `quartz/.github/`）：

- 触发：push 到 `main`
- 步骤：checkout(fetch-depth:0) → setup-node 22 → npm ci → `npm run install-plugins` → `npx quartz build` → upload `quartz/public` → deploy-pages
- 全部构建步骤 `working-directory: quartz`（因 Quartz 在子目录）
- **无 rsync**（content 已在仓库中追踪）
- 缓存 `~/.npm` 与 `quartz/.quartz/plugins`（key 用 `quartz.config.yaml` + `package-lock.json` 哈希）

发布：仓库 Settings → Pages → Source = GitHub Actions；URL = `https://chartreuse310.github.io/chinese-architecture-wiki/`。

### 4.5 更新（ingest）流程

每次用户提供新 vault 时：

1. 把新 vault 放到 `chinese-architecture-wiki-vault/`（覆盖旧目录）；
2. **镜像 + 转换**到 `quartz/content/`：按 §4.2 映射规则重命名、重构 frontmatter、更新链接；与现有 `content/` 对比，仅应用增/改/删（`git diff` 辅助）；
3. 转换完成后**删除 vault 目录**（vault 不入库）；
4. 提交 `content/` 变更并推送，CI 自动构建发布。

> 转换含人工判断（拼音分词、新词 slug），非全自动脚本；映射表随内容增长在本文档维护。
