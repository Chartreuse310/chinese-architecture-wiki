## 2026-07-23 — vault 被误就地改造（架构认知错误）
- **现象**：第 3 轮后，直接在 `chinese-architecture-wiki-vault/` 内重命名文件、改 frontmatter，破坏了 vault 原件。
- **原因**：误以为 vault 是被追踪的内容源、需就地改造。用户纠正：vault 是临时输入，应「镜像+转换」到 `quartz/content/`（追踪源）后删除 vault，不碰原件。
- **修复**：第 4 轮纠正架构——vault 改为 gitignore 的临时输入；转换结果镜像到 `quartz/content/`（15 文件，已正确）；vault 不入库。
- **验证**：`quartz/content/` 内容与链接正确；vault 已 gitignore，不影响仓库。
- **关联**：01 §4.1/§4.5；02 第 4 轮。vault 清理（恢复原状或删除）待与用户确认。

## 2026-07-23 — 构建报 `Could not resolve "../../.quartz/plugins"` 与 `Found 0 input files`
- **现象**：`npx quartz build` 报 `Could not resolve "../../.quartz/plugins"`（Head.tsx 导入）；修复导入后又提示 `Found 0 input files from content`。
- **原因**：
  1. 未生成 `.quartz/plugins` 索引——v5 需 `npm run install-plugins`（读 `quartz.config.yaml` 生成），`npx quartz build` 不会自动触发 `prebuild`。
  2. 根 `.gitignore` 含 `quartz/content/`，而构建用 globby 且 `gitignore: true`，把内容文件当作被忽略而排除。
- **修复**：
  1. 本地与 CI 在 build 前先 `npm run install-plugins`。
  2. 根 `.gitignore` 移除 `quartz/content/`（content 改为追踪的规范内容源）；仅忽略 vault、node_modules、public、.quartz。
- **验证**：重新构建 `Parsed 15 Markdown files`、`Emitted 108 files`。
- **关联**：01 §4.4；`deploy.yml`。

## 2026-07-23 — sitemap 的 baseUrl 格式错误（`https:///...`）
- **现象**：sitemap.xml 出现 `https:///chinese-architecture-wiki/concepts/...`（三斜杠）。
- **原因**：`baseUrl` 设成路径 `/chinese-architecture-wiki/`；v5 期望 host（不含协议/首尾斜杠），用于拼接绝对 URL。
- **修复**：改为 `chartreuse310.github.io/chinese-architecture-wiki`（GitHub 用户名 Chartreuse310，Pages URL 小写）。页面内链接本就是相对路径，子路径下天然可用。
- **验证**：sitemap 显示 `https://chartreuse310.github.io/chinese-architecture-wiki/concepts/...`。
- **关联**：01 §4.3；`quartz.config.yaml`。

## 2026-07-23 — `npx quartz plugin install` 不适用（无 lockfile）
- **现象**：CI 用 `npx quartz plugin install` 提示 `No quartz.lock.json found`。
- **原因**：该命令用于从 lockfile 安装 Git 插件；本项目只用 npm 插件（已在 `package.json` 依赖），无 lockfile。
- **修复**：`deploy.yml` 改用 `npm run install-plugins` 生成 `.quartz/plugins` 索引；插件缓存 key 用 `quartz.config.yaml` + `package-lock.json` 哈希。
- **验证**：本地 `npm run install-plugins` 后构建通过。
- **关联**：`deploy.yml`。

## 2026-07-23 — KaTeX 对公式中中文变量名报警告
- **现象**：构建大量 `LaTeX-incompatible input ... unicodeTextInMathMode` 警告（如 `阔`、`斗`、`栱`）。
- **原因**：公式 `$开间面阔 = 斗栱攒数 * 斗栱宽$` 含中文变量名，KaTeX 不支持 math 模式中的 CJK。
- **修复**：把公式中中文用 `\text{}` 包裹，如 `$\text{开间面阔} = \text{斗栱攒数} * \text{斗栱宽}$`；单位 `寸` 同样包裹为 `2.5\text{寸}`。
- **验证**：重新构建，`unicodeTextInMathMode` 警告由 ~46 降为 0，构建通过（15 文件 / 108 输出）。
- **关联**：01 §6；涉及 `content/concepts/miankuo.md`、`content/refs/ma-bingjian-muzuo-yingzao-jishu/1.2.1-miankuan-queding-fangfa.md`。
